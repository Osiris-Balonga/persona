# Private portrait delivery

The portrait Worker reads a private R2 bucket through its binding. It has no upload, delete, or listing route. The versioned production manifest lists 3,208 approved portraits (1,764 standard, 684 doctor and 760 construction portraits) and 9,624 WebP objects: one large, medium, and thumbnail rendition per portrait, each with a SHA-256 value. Doctors cover all 19 production collections, with 36 portraits per collection and two per gender per eligible review band from ages 25 to 64. The 512-pixel `large` object is also the canonical reviewed source. The public API selects approved images by production collection, gender, and apparent age range, and returns the three rendition URLs in `picture`.

The doctor releases use production IDs `p_1768` through `p_2451`, retaining all standard IDs, keys and hashes. Its owner-authorized delegated review decisions, source-to-quadrant hashes, local-to-production ID crosswalk and recovered-prompt association caveats are retained outside Git with the release evidence. The final 288 doctors (Americas, Europe and Oceania) were supplied by the owner as 72 original four-person sheets. Their original archive and sheet hashes, deterministic quadrant extraction and delegated review decisions are retained; exact cloud generation prompts and backend model identification were not supplied and are not represented as verified. All three renditions must pass the existing strict 50,000-byte limit before upload.

## Publication boundary

The construction release adds IDs `p_2452` through `p_3211`, preserving all previous IDs, keys and hashes. Each of the 19 collections has 40 portraits, two per gender per adult review band from 18 to 64. Original sources and archive hashes, deterministic crop coordinates, delegated review decisions and the local-to-production ID crosswalk are retained outside Git. Three unreadable European sources were replaced; three rectangular Southeast Asian sources were square-cropped within each quadrant without stretching. The owner explicitly accepted the recorded recurring-face patterns in the reviewed Asian, African and Oceanian lots for this delivery. This exception does not establish unique identities; distinct hashes establish different files only. Recovered visible or revised prompts are distinguished from exact submitted prompts, and unavailable cloud backend identification is not asserted.

The [review/import procedure](portrait-review.md) must approve each asset first. Upload only approved WebP files to the exact versioned object keys in the manifest and set R2 custom metadata `sha256` to each file's reviewed hash. The 512, 256, and 64 pixel objects use `portraits/v1/large/p_0001.webp`, `portraits/v1/medium/p_0001.webp`, and `portraits/v1/thumbnail/p_0001.webp`. In the R2 object browser, open `portraits`, then `v1`: these three folders should be the only entries. Configure the manifest's HTTPS `publicBaseUrl` to the Worker's final public origin. The Worker matches the entire key against an approved catalog entry and checks R2's size and hash metadata before serving. A missing, rejected, withdrawn, replaced, or metadata-mismatched object returns `404` and `no-store`.

The R2 bucket `persona-portraits` must have no public `r2.dev` endpoint or public custom domain. Bind it to the Worker as `PORTRAITS`; do not expose R2 credentials to API clients. The Worker permits only `GET` and `HEAD`, streams successful `GET` bodies, and returns `Content-Type: image/webp`, `ETag`, `X-Content-Type-Options: nosniff`, and `Cache-Control: public, max-age=300, must-revalidate`. `If-None-Match` uses weak comparison for both methods and supports validator lists and `*`. Approval, availability, and stored hash checks run before returning 304. Query-string transformations are denied; each rendition has its own ordinary purgeable URL path.

The production isolate validates its static, versioned manifest once and prepares an approved-key/hash snapshot. Stored object hashes and availability are still checked on every request. A changed or withdrawn catalogue requires a fresh delivery instance/deployment and the existing purge procedure; mutable review catalogues must create a fresh instance after edits. Invalid catalogues fail closed.

For this account, the public origin is `https://persona-portraits.osirisbalonga.workers.dev`. The R2 bucket itself stays private. To publish a reviewed batch, run `npm run portraits:audit-review`, then start `npx wrangler dev --config wrangler.portraits-upload.jsonc --ip 127.0.0.1 --port 8788`. In another terminal run `npm run portraits:publish`. The local upload Worker uses a remote R2 binding, checks each payload hash, records it as R2 custom metadata, and refuses to overwrite a changed key. The publishing command checks all reviewed files before uploading and writes the versioned manifest only after every object succeeds. Stop the local upload Worker when finished. It is never deployed publicly.

For rendition publication, `npx tsx scripts/prepare-portrait-variants.ts` verifies each approved 512 pixel source, prepares the three WebPs, and writes a local manifest proposal. After reviewing and installing that proposal, run `npx tsx scripts/publish-portrait-variants.ts --publish` with the same local upload Worker running. This publisher verifies all rendition bytes and hashes before its first R2 write, then confirms each key was uploaded or already matched. The initial rendition publication reported 3,804 newly uploaded and 1,488 already present variants. A later inventory and cleanup removed the 1,764 redundant root-level copies after verifying their `large` counterparts.

The review console continues to use local, Git-ignored masters, optimized WebPs, and review state. Approved WebPs are copied to R2; neither the image files nor the local review state are committed to GitHub. Changes made in the console after publication require another reviewed import and Worker deployment.

## Verification and withdrawal

Before deployment, run `npm run typecheck:worker`, `npm run test:unit -- portrait-worker`, and `npm run build:worker` (Wrangler dry run). Configure the final route/domain and verify approved large, medium, and thumbnail URLs with `GET` and `HEAD`, an unknown ID, and the bucket's private exposure settings. The completed live checks returned `GET 200` for all three sizes of `p_0001`, `p_0500`, and `p_1767`, `HEAD 200` for `p_1767` medium, and `404` for rejected `p_1600` and unknown `p_9999`. A 2026-09-28 content check also downloaded all three variants of `p_0001` and thumbnails of `p_0500` and `p_1767`; WebP dimensions were 512, 256, and 64 pixels as applicable, and each SHA-256 matched the manifest. This is sampled content verification alongside the complete key inventory.

To withdraw an asset, remove its approval and deploy the new manifest first, then [purge its three rendition URLs globally](https://developers.cloudflare.com/cache/how-to/purge-cache/purge-by-single-file/) and verify that fresh `GET` and `HEAD` requests return `404` with `no-store`. Purging only a local Worker Cache API entry does not evict the CDN globally. Previously fetched browser copies may remain fresh for up to five minutes. Replacements use new versioned keys; never overwrite an approved key in place.
